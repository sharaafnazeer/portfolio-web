A small but opinionated reference for building Spring Boot services where the
**OpenAPI spec is the contract**, not an afterthought. The spec drives both
server-stub generation and a typed TypeScript client — frontend and backend
teams can work in parallel from day one.

## What it shows

- A complete CRUD API for an `Employee` resource, designed spec-first.
- The `openapi.yaml` lives in the repo and is reviewed in PRs like any other
  source file.
- `openapi-generator-maven-plugin` generates Java interfaces at build time;
  controllers `implements` those interfaces, so drift is impossible.
- Contract tests via [Schemathesis](https://schemathesis.readthedocs.io/) run
  in CI against a Testcontainers-managed Postgres.
- Swagger UI is exposed at `/swagger-ui` for live exploration.

## Why it matters

Most teams say they do API-first; in practice they design as they code. The
result is APIs that leak implementation details and break clients silently.
This repo demonstrates the minimum tooling needed to make the discipline stick.
